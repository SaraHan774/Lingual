# /wrap-up — Session-End CLAUDE.md Sync

너는 이 스킬이 호출되는 동안 세션을 돌아보며 `CLAUDE.md` 와 `CLAUDE.local.md` 에 반영할 가치가 있는 **비자명한** 변화만 추출해 반영한다. 장황해지지 않도록 **추가만큼 트리밍도 본다**.

## 설계 원칙 (Anthropic 공식 가이드)

- **이중 필터 질문 — 둘 다 Yes 여야만 통과**:
  - (a) **실수 예방 가치**: 이 문장이 빠지면 다음 세션의 Claude 가 실제로 실수를 할까?
  - (b) **상시 로드 가치**: 앞으로 **모든 다른 세션**에서 의미가 있고, **매 세션 시작마다** context window 에 다시 로드할 만큼 자주 필요한 정보인가?
  - CLAUDE.md / CLAUDE.local.md 는 세션 시작마다 무조건 로드된다 → 여기 들어가는 모든 줄은 **토큰 비용을 영구적으로 부과**한다. 한쪽이라도 No 면 다른 곳으로 보낸다(아래 "대체 위치").
- **길이 목표**: `CLAUDE.md` < 150줄, `CLAUDE.local.md` < 80줄 권장. 초과하면 추가 전에 트림.
- **자동 추론 가능한 것은 쓰지 않음**: 빌드 설정(`libs.versions.toml`, `build.gradle.kts`), 폴더 구조, 표준 언어 관습, 커밋 메시지 스타일 등은 파일/git log 를 읽으면 되므로 제외.
- **린터가 할 일은 쓰지 않음**: 포매팅·임포트 정렬·네이밍 규칙의 상세.
- **자명한 조언 금지**: "깨끗한 코드를 쓰세요", "테스트를 작성하세요" 류.

### 대체 위치 (필터 (a) 는 통과했지만 (b) 는 실패한 경우)

| 성격 | 넣을 곳 |
|---|---|
| 특정 영역에서만 비자명 — 그 영역을 건드릴 때만 필요 | 해당 파일의 한 줄 주석, 또는 해당 영역의 PRD/docs |
| 특정 에이전트 실행 시에만 필요 | `.claude/agents/<name>.md` 내부 |
| 사용자 선호·피드백·진행 상황 | auto memory (`memory/` 시스템) |
| 일회성 작업 결과·세션 로그 | `git log` / PR 설명 |

## 역할 분리

| 저장소 | 내용 | 커밋 여부 |
|---|---|---|
| `CLAUDE.md` | 팀 공유 프로젝트 규칙·gotcha. 누가 이 리포를 열어도 필요한 것. | 커밋 |
| `CLAUDE.local.md` | 개인 개발 환경·로컬 인프라(로컬 스킬/에이전트, 로컬 배포 경로) | `.gitignore` |
| `memory/` (auto memory) | 사용자 프로필, 피드백, 진행 중인 프로젝트 컨텍스트 | 세션 간 자동 로드 |

**구분 기준**: 리포 고유 사실 → CLAUDE.md. 이 사용자의 개인 셋업 → CLAUDE.local.md. "사용자가 어떻게 일하길 원하는가" → memory. **CLAUDE 문서에 memory 성격의 내용 (사용자 선호·피드백·경고) 을 넣지 않는다.**

## 워크플로우

### 1) 현 상태 로드

- `Read` 로 `CLAUDE.md`, `CLAUDE.local.md` 를 가져온다. 없으면 생성 스킵.
- 각 파일의 총 줄 수를 측정. 150/80 초과 시 트림 후보를 먼저 훑는다.

### 2) 세션 스캔 — 후보 추출

이번 세션 대화를 훑어 아래 카테고리의 **비자명** 변화만 후보로 뽑는다:

- **새 gotcha / trap** — "이렇게 짜면 컴파일 실패한다", "이 enum 을 우회하면 안 된다" 같은 발견.
- **제거된 기능·모듈** — 사라진 패키지/폴더가 문서에 남아 있으면 트림 대상.
- **새 로컬 인프라** — 이번에 만든 skill / agent / 헬퍼 스크립트.
- **변경된 경로·이름** — DB 파일명, 주요 라우트명 등.
- **새로운 명령** — 이번에 도입한 `./deploy.sh`, `/ship` 같은 실행 경로.
- **외부 시스템 포인터** — Firebase 프로젝트, Linear 보드, Grafana 보드 (해당 시).

**후보에서 제외**: 코드에서 직접 읽히는 사실, 일회성 작업 결과, 리뷰 논의 중 나온 선호("이번엔 이렇게 하자"), 사용자 피드백·선호. 후자는 memory 로 간다.

### 3) 필터 + 분류

각 후보에 대해 아래를 결정:

1. **이중 필터 통과?** — (a) 실수 예방 가치 **AND** (b) 상시 로드 가치. 둘 다 Yes 가 아니면 CLAUDE 문서에 넣지 않고 "대체 위치" 표를 따른다.
2. **저장 위치**:
   - 리포 전체에 적용되는 규칙/아키텍처/gotcha → `CLAUDE.md`
   - 로컬 개발·개인 환경·로컬 에이전트 → `CLAUDE.local.md`
   - 사용자 선호·피드백·프로젝트 현황 → memory 시스템 (이 스킬에선 다루지 않음, auto memory 가 처리)
3. **형식**: 한 줄 bullet 또는 짧은 문단. 장황한 튜토리얼 금지.
4. **중복 체크**: 이미 문서에 있는 사실이면 drop.

### 4) 트림 후보 식별

현재 문서에서 아래 조건의 줄을 트림 후보로 표시:

- 이미 제거된 기능·경로를 가리키는 줄 (예: 삭제된 모듈 언급)
- 현재 `build.gradle.kts` / `libs.versions.toml` 과 불일치하는 값
- 표준 Android/Kotlin 관습 (AS 버전, JDK 11+, gradle --parallel 같은)
- 자명한 조언
- 동일 사실의 중복

### 5) 사용자 승인 + 적용

- **AskUserQuestion** 로 요약된 변경안을 보여준다. 각 질문은 논리적으로 묶인 diff 한 덩어리 기준. 예:
  - Q1: "`CLAUDE.md` 에 'X 규칙' 추가할까요?" / "이미 있음·불필요·추가 (Recommended)" 같은 옵션.
  - Q2: "`CLAUDE.local.md` 에서 'stale AR 섹션' 제거할까요?"
- 후보 수가 많으면(>4) 한 번에 다 묻지 말고, 문서별로 묶어 2번 나눠 묻는다. `AskUserQuestion` 은 질문 최대 4개 제한.
- 승인된 것만 `Edit` 로 반영. 한 문서에 여러 변경이 있으면 순서대로 적용.
- **절대 git add/commit 하지 않는다.** 사용자가 별도 요청해야 커밋.

### 6) 요약 보고

적용 후 사용자에게 2~4줄로:

- 추가된 항목 개수 / 삭제된 항목 개수
- 두 파일 현재 줄 수
- 남은 제안 (예: "CLAUDE.md 가 여전히 140줄. 시간 날 때 Architecture 섹션 프로즈를 bullet 로 압축 권장")
- memory 로 빠진 후보가 있으면 "다음 항목들은 memory 쪽에서 기록하는 게 더 적합합니다" 로 지나가듯 언급.

## 절대 하지 말 것

- 문서를 **장식성 업데이트** 로 부풀리지 말 것 ("최근 세션에서 X 를 논의함" 같은 로그 기록 금지 — 그건 git log 의 역할).
- 사용자 피드백·선호·한 번의 의사결정을 CLAUDE 문서에 옮기지 말 것. 그건 memory/feedback 의 영역.
- 승인 없이 **덮어쓰기 (Write)** 하지 말 것. `Edit` 로 핀포인트 수정.
- 이 스킬 실행 중에는 git commit/push 를 절대 자동 실행하지 말 것. 사용자가 명시 요청해야 함.
- 사이클 상태(`/ship` 의 `.claude/cycles/*`) 나 에이전트 정의 같은 **운영 파일** 을 wrap-up 에서 건드리지 말 것. 이 스킬은 `CLAUDE.md` / `CLAUDE.local.md` 에만 작용.
- 코드 파일·테스트·`docs/prd/*` 수정을 wrap-up 에 끼워 넣지 말 것. 본 스킬의 범위 밖.

## 호출 예시

- `/wrap-up` 또는 사용자 "이 세션 마무리하자" → 세션 스캔 → 후보 추림 → 필터 통과한 3~4건을 AskUserQuestion 으로 승인 → Edit 반영 → 요약.
- 이번 세션에 한 게 많지 않으면 "추가/삭제할 것 없음" 으로 2줄 보고하고 종료.
- `CLAUDE.md` 가 180줄로 이미 팽창 상태 → 추가는 보수적으로, 트림 제안을 먼저.
